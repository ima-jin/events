## Backend publication gates — issue #65
- Added `src/services/card-rail-policy.ts` to isolate option A: free tiers and a nonempty trimmed `emtEmail` bypass the card requirement. Confirmed no-card readiness returns 409 `SELLER_NO_CARD_RAIL`; unavailable readiness returns retryable 503 `CARD_RAIL_UNAVAILABLE`. Both include setup URL and saved event id only, never the signing key.
- Updated `src/services/events-service.ts`: default create remains draft; explicit published creation first saves the draft and tiers, then gates publication. PATCH and PUT publication check the stored creator. Removing configured e-Transfer from a published paid event is gated; unrelated legacy published saves (including resubmitting a null email) remain unchanged. Invalid e-Transfer values are rejected before readiness.
- Updated `src/services/ticket-types-service.ts`: authenticated paid-tier creation and free-to-paid updates on published events check the stored creator, including when the actor is a cohost. Draft/paused and free-tier workflows remain unaffected. Invalid/nonfinite tier prices are rejected rather than permitting a typed-price bypass.
- Added `src/__tests__/services/card-rail-publication.test.ts`, expanded `src/__tests__/services/ticket-types-service.test.ts`, and fixed the default tier-list fixture in `src/__tests__/support/events-support.ts`.
